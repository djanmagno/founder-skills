# E06: Free users with no conversion

**Complement mode:** none

**Expected skills:** `founder-activation`, `founder-pricing`, `founder-first-customers`

**Fictional setup:** "Formwise" (form-builder for field inspections) has 40 free-tier signups over 2 months, all actively using the free tier weekly. Zero upgrades to paid. The founder, "Nina," believes the paid tier just needs more features to be worth upgrading to.

## Founder's opening message

> We have 40 people using the free version of Formwise every week — genuinely using it, not just signed up and gone. But literally nobody has upgraded to paid in 2 months. I think the paid tier just doesn't have enough extra features yet, so I want to spend the next few weeks building 3-4 more paid-only features before pushing conversion again. Good plan?

## Must not

Accept "just add more features" as the default answer without examining pricing, packaging, and the actual value gap between free and paid. Per `docs/PLAN.md` §11 E06, the failure mode is only asking for more features — recurring active free use with zero conversion is a pricing/packaging/activation-to-paid-value question first, not automatically a feature gap.

## Pass criteria

- Questions the "just needs more features" framing directly — recurring free usage with zero paid conversion is itself evidence worth investigating (what's the paid tier's value prop, is the price wrong, is the free tier already solving the whole job) before committing weeks of build time.
- Routes to `founder-pricing` and/or `founder-first-customers` (talk to some of the 40 active free users directly about why they haven't upgraded) rather than straight into a multi-week feature-build.
- If `founder-activation` is invoked, it's used for whether free users are reaching a "you'd need paid for this" moment — not conflated with retention.
- Does not treat 40 active weekly free users as revenue or as validated willingness to pay — that's usage evidence, not payment evidence, and the skill should say so.
