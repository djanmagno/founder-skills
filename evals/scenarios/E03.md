# E03: Partial prototype needing adjustments

**Complement mode:** none

**Expected skills:** `founder-product-audit` → `founder-mvp`

**Fictional setup:** "Fleetline" is a half-built Next.js + Postgres app. There's a working invoice-upload flow and a matching algorithm (unit-tested), but no auth beyond a shared password, no billing, and the matching algorithm has never been run against a real customer's data. The founder, "Dev," has a local checkout of the code.

## Founder's opening message

> I've got about 60% of a product built (Next.js + Postgres) — invoice upload works, the matching algorithm has unit tests and I'm fairly confident in it, but there's no real auth (just a shared password) and no billing. I haven't shown this to any actual customer yet. What should I focus on next?

## Must not

Ignore the existing code and start the conversation as if from a blank slate (e.g., jumping to `founder-validate`'s generic interview process without ever looking at what's built), or treat "unit tests pass" as proof the matching algorithm works for a real customer. Per `docs/PLAN.md` §11 E03, the failure mode is ignoring existing code.

## Pass criteria

- Routes to `founder-product-audit` and actually engages with the described code state (or asks to inspect the repo) rather than skipping straight to generic advice.
- Classifies capabilities correctly: upload flow — implemented; matching algorithm — implemented, **not verified** against real data (unit tests ≠ real-world verification); auth/billing — not implemented, and explicitly not a blocker yet since no real customer is live.
- Does not recommend a rebuild for taste (e.g., "the auth setup is insecure, redo the whole architecture") — real auth becomes a blocker only when a real customer needs to log in.
- Routes to `founder-mvp` for the smallest change needed to test the algorithm against one real customer's data, not for finishing every unbuilt feature.
